# HO-TEL-SCN-20260829-01 — TEL worker will edit `flowPanel.ts`

- **From:** BW (on behalf of TEL)
- **To:** SCN
- **Date:** 2026-08-29
- **Type:** cross-file ownership notice
- **Dispatch:** `active/DSP-TEL-20260829-02-flow-live-assets.md`

## What

The Output Flow / Live JSON panel keeps showing assets that have been deleted from the project — the operator's example is a drone deleted from the fleet that is still listed. The cause spans two owners:

- `src/telemetry/flowTap.ts` (**TEL**) keeps every id it has ever seen and is never reset outside tests.
- `buildFlowCards` in `src/scene/flowPanel.ts` (**SCN**) unions the fleet registry with every id in the tap, so a deleted id is added straight back after the registry drops it.

## Why it is one dispatch, not two

Splitting it would leave a tap that can forget paired with a panel that still re-adds, or vice versa — two half-working dispatches and a merge seam through a single behaviour. BW assigned both files to the TEL worker.

## Scope limit SCN can hold BW to

The TEL worker's edit to `src/scene/flowPanel.ts` is confined to the **card-selection rule inside `buildFlowCards`** and its unit test. No layout, no styling, no panel structure, no change to the Live JSON toggle or the ≤4 Hz poll rate. Anything beyond that comes back to SCN as its own dispatch.

## The rule being implemented (BW decision)

Restricting the panel to the fleet registry was rejected: seeing an id that is arriving on the wire but is *not* in the fleet is how an operator notices a producer sending `dji-7` when the fleet says `1`. Instead:

- A registry id is always shown, even with no traffic.
- A non-registry id is shown only while actively receiving, within a short recency window (starting value 5 s).
- The tap is pruned on fleet change and project load, so deletion gives immediate feedback.

`buildFlowCards` must take the current time as an argument so it stays a pure, testable function.

## Action for SCN

Note it in `SCN_MEMO`. No implementation. Review the diff when the worker reports if you want to confirm the scope limit held.
