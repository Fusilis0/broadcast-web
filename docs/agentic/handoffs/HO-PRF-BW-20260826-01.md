## Summary
Operator asked PRF (2026-08-26) for **general improvements** and **60 fps on preview, AR, 3D, and 2D**, plus “computer doesn’t use a lot of GPU / make sure it uses some / resource use is fine / good stream experience.”

PRF **refuses** a silent cap change. `STUDIO_TICK_FPS = 60` and NDI 3D @ 60 with terrain+ocean+`readPixels` stay a **new BW phase**, not a DSP-PRF. Measurement worker `DSP-PRF-20260826-01` is issued first.

## Decisions / facts
- Locked today: preview ~60 rAF · AR NDI ~30 · 3D NDI ~10 · 2D off@10 · `STUDIO_TICK_FPS = 30`.
- Air camera is typically **~30 fps**. AR NDI @ 60 would duplicate frames into vMix, not add picture information.
- 2D map @ 60 is wasted broadcast graphic cadence.
- 3D @ 10 **will look stuttery** in vMix — that is the cap, not a missed 60 Hz clock. Raising it without async readback re-opens the 2026-08-12 UI-freeze (`readPixels` stall).
- Dual-GPU: Electron already sets `force_high_performance_gpu`; WebGL context does **not** set `powerPreference`. Idle dGPU + glitchy UI is the classic iGPU path.
- Default env is **simple** (cheap). GPU load shows up when realistic + terrain are on.
- Preview ~60 was **never Electron-smoked** (OUT-18-01). Live NDI send fps is **not** on the Output rail today (static copy only).
